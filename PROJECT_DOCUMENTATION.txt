1. THE PROBLEM
================================================================================

Every CPSE (CPCL, IOCL, NTPC, SAIL, GAIL…) runs its own ERP with its own
material master. The same physical item is described in five different
ways, under five different codes, in five incompatible databases:

    CPCL   MAT100006   "HEX BOLT BLK OX, 8.8, M20x80"            UOM: NOS  ₹19
    IOCL   RM-00006    "Hex Bolt – Black Oxide – DIN 933 – 8.8
                        – M20 X 80"                              UOM: EA   ₹19
    NTPC   EGW000004  "Hex Bolt, M20 x 80 mm, Blk Ox,
                        Gr.8.8, DIN 933"                        UOM: NOS  ₹21
    SAIL   S100028     "HEX BOLT / DIN-933 / M20x80MM /
                        BLACK / 8.8 GR"                         UOM: NUM  ₹16
    GAIL   GLM-HB-0001 "HEX BOLT M20X80 GR 8.8 BLACK DIN 933"   UOM: NOS  ₹18

One bolt. Five identities. A price spread from ₹16 to ₹21 on the very
same item — pure friction, zero engineering difference.

The consequences of this fragmentation:

  * No aggregated demand. Five CPSEs buying the same bolt in five small
    lots cannot pool volumes, so they lose bulk-discount leverage.
  * Price spread nobody sees. The same material costs up to 51% more at
    one CPSE than another (a ₹26,674 vs ₹54,000 centrifugal pump in our
    own data), because nobody can compare like-for-like.
  * Duplicate catalogs. Each CPSE maintains the same items independently
    — duplicated effort, inconsistent specifications, typo-driven ghosts.
  * Wrong merges are catastrophic. A grade 8.8 bolt must NEVER be
    catalogued as a grade 10.9 bolt (or vice versa) — in a refinery or
    a power plant, a mixed-up fastener is a safety incident. So any
    solution must merge aggressively AND be provably safe.
  * Legacy data is messy. Free-text descriptions, three different UOM
    words for "each", typos ("CASr STEEL", "Thermofell"), mixed formats.
    Pure-string matching is hopeless; pure-AI guessing is dangerous.

The problem statement asks for an AI-driven system that standardizes
and harmonizes material codes across CPSEs — without false merges,
without losing the human accountability that government procurement
requires.


================================================================================
2. OUR IDEA
================================================================================

Our core principle:

        "AI proposes. Hard facts dispose. Humans approve."

We do NOT let a neural net decide merges on its own — similarity alone
is exactly how 8.8-grade bolts get merged with 10.9-grade bolts. Instead
we built a three-lock pipeline:

  LOCK 1 — ENGINEERING FACTS VETO THE AI.
        Every record is parsed into ~35 hard engineering attributes
        (grade, thread, material, schedule, size, voltage…). If two
        records share an attribute and the values conflict, the pair is
        rejected no matter how similar the text looks. A 0.94-similarity
        pair with 8.8 vs 10.9 is REJECTED. This is what makes dangerous
        merges impossible by design.

  LOCK 2 — MISSING IDENTITY GOES TO A HUMAN, NEVER AUTO-MERGED.
        A record missing its family's identity attributes (a bolt with
        no grade) is ambiguous by definition. The AI proposes the most
        likely national code; a CPSE officer confirms or rejects with one
        click. Every decision is logged. This turns "risky automation"
        into an auditable governance workflow.

  LOCK 3 — CODES ARE DETERMINISTIC, NOT SEQUENTIAL OPINIONS.
        The National Material Code (NMC) is a salted SHA-1 hash of the
        material's canonical attribute form. The same material always
        maps to the same code — across CPSEs, across runs, across
        machines — and two genuinely different materials can never
        collide onto one code.

With those locks in place, the AI (sentence embeddings) does what it is
actually good at: recognizing that "Black Oxide Hex Bolt DIN 933" and
"HEX BOLT / DIN-933 / BLACK" are the same thing despite totally
different phrasing.

3. HOW WE TACKLED IT — THE PIPELINE, LAYER BY LAYER
================================================================================

The system is a Python pipeline (src/) with a Streamlit officer
dashboard (src/app.py). Data flows: raw CSVs → normalize → match →
cluster → standardize → master + mapping + audit, with a review loop
for humans.

LAYER 1 — SYNTHETIC CPSE DATA (src/generate_dataset.py)
    WHY: No real CPSE data is public, and we needed ground truth to
    PROVE our metrics. So we generated 5 realistic ERP catalogs (403
    records) with authentic mess: different code schemes, three UOM
    spellings for "each" (NOS/EA/NUM), free-text vs slash-separated
    formats, injected typos ("CASr STEEL", "Placn", "Thermofell"), and
    — critically — deliberate NEAR-MISS TRAPS: same bolt, one grade
    apart (8.8 vs 10.9). Every record carries a hidden true_material_id
    so precision/recall are measured, not claimed. A 15-record GAIL
    file doubles as the live CSV-upload demo (it runs in "production
    mode": unlabeled uploads are ingested but excluded from scoring).

LAYER 2 — NORMALIZATION (src/normalize.py)
    WHY: Matching is only as good as the facts extracted. ~35 regex
    rules convert each free-text description into a structured
    attribute dictionary ({"grade": "8.8", "thread": "M20x80",
    "material": "SS316", "schedule": "40", …}), normalize UOMs
    (NUM/EA → NOS), classify the fine type and category, and compute a
    canonical normalized string. This layer is deterministic and
    auditable — no black boxes before the facts are on the table.

LAYER 3 — MATCHING (src/match.py)
    WHY: Two records are the same item only if semantics AND facts
    agree. Embeddings (SentenceTransformer, CPU-forced for stability,
    with a TF-IDF offline fallback) provide semantic similarity between
    normalized descriptions. Blocking by category/family keeps the
    pair-space tractable. Then pair_verdict applies the locks:
      · Veto: any conflicting shared attribute, type, or category
        → rejected (7,951 pairs rejected this run — including all the
        traps: 0 violations).
      · Review: either record missing identity attributes
        → held for a human (959 pairs).
      · Match: facts agree + score clears the threshold
        → accepted with a confidence score.
    Confidence blends similarity (55%), attribute overlap (30%), and
    fuzzy string ratio (15%) so a pair needs evidence, not vibes.

LAYER 4 — CLUSTERING (src/match.py, cluster())
    WHY: Pairwise matches must become catalogs. Union-find merges
    accepted pairs into clusters ("this CPCL bolt + this IOCL bolt +
    this NTPC bolt are ONE material"). A weakest-link repair step
    splits clusters that would contain internal contradictions — the
    cluster's confidence is its weakest internal accepted edge, so a
    shaky chain never hides inside a confident-looking group.

LAYER 5 — STANDARDIZATION (src/standardize.py)
    WHY: One national identity per real material. Each cluster gets a
    master record: majority-vote attributes (with first-appearance
    tie-breaks), a standardized description ("HEX BOLT | M20X80 | 8.8 |
    BLACK | DIN 933 | NOS"), and its NMC — the deterministic salted
    hash. Indistinguishable twins (two records with identical text but
    no distinguishing attributes) are quarantined as PROVISIONAL —
    surfaced for officer review rather than silently merged. A
    collision registry extends codes in the (so far never-seen) case of
    a hash collision, and the registry resets every run so codes are
    stable across uploads.

LAYER 6 — PIPELINE + GROUND-TRUTH EVALUATION (src/pipeline.py)
    WHY: Government adoption requires proof, not demos. The pipeline
    orchestrates everything and scores it against hidden truth labels:
    pairwise precision/recall/F1 on the 388 labeled benchmark records,
    trap violations (MUST be 0), cross-CPSE merge rate, and potential
    recall after officer approval. Every run writes auditable CSVs to
    outputs/: unified_master.csv, code_mapping.csv, review_queue.csv,
    rejected_pairs.csv, review_decisions.csv, audit_log.csv.

LAYER 7 — OFFICER DASHBOARD (src/app.py, Streamlit)
    WHY: The review queue only works if reviewing is effortless and
    trustworthy. Four tabs:
      · Overview — KPIs (records, codes, shared materials, precision,
        price spread), status chips, charts, CSV exports of the master
        and mapping.
      · Review Queue — each held record in an expander with a SPEC-DIFF
        MATRIX (green = identical attributes, amber = differing, gray =
        missing), a "Why this match?" line listing the attributes the
        AI agreed on, per-CPSE color dots, and one-click
        Approve/Reject that is logged to the audit trail.
      · Code Lookup — type any legacy code (or click a quick-pick) →
        its National Material Code, standardized description, sharing
        CPSEs, price spread, and all equivalent legacy codes.
      · Audit Trail — every machine action and officer decision,
        exportable.
    The sidebar accepts a live CSV upload (the GAIL demo): column
    validation, one click re-harmonization, instant integration.

LAYER 8 — SMOKE TEST (scripts/smoke_check.py)
    WHY: The UI's data contract must never silently break. It checks
    that records carry the fields the UI expects, every review row
    resolves to a real record, master NMCs are non-empty, and the
    mapping covers every record — exiting 0/1 so it can gate any future
    change.

4. WHAT WE HAVE IMPLEMENTED — FEATURES AND VERIFIED RESULTS
================================================================================

FEATURES
  · Full 5-CPSE harmonization: 403 records → 267 National Material Codes
  · 403/403 legacy→NMC mappings (every record maps to exactly one code)
  · Live CSV upload + re-harmonization inside the dashboard (GAIL demo)
  · Hard-attribute veto engine with zero false merges
  · Human review queue with spec-diff matrix, matched-attribute
    rationale, and persistent, logged decisions
  · Deterministic, collision-safe National Material Codes
  · Deterministic outputs: identical inputs → byte-identical NMCs
  · Demand-aggregation view: shared materials + per-NMC price spread
  · Full audit trail (machine + officer actions)
  · Government-minimal, institutional-blue Streamlit UI
  · 9-slide pitch deck built entirely on the real verified numbers

VERIFIED RESULTS (this run, 403 records / 5 CPSEs)
  · Auto-merge precision            1.000  (every auto-merged pair correct)
  · Recall (auto)                   0.357
  · Potential recall w/ officers    89.7%  (governance recovers ambiguity)
  · Trap violations                 0      (8.8 vs 10.9 bolts NEVER merged)
  · Veto rejections                 7,951 pairs
  · Review queue                    155 items (959 ambiguous pairs)
  · Cross-CPSE materials merged     67/105 (63.8%) auto
  · Materials shared by 2+ CPSEs     68  (the aggregation opportunity)
  · Average price spread            12.6% across shared materials
  · Runtime                         ~10 seconds, CPU only

Real spread examples from our own data:
  · Centrifugal pump 25 m3/hr, 32 m   — ₹26,674 vs ₹54,000  (51%)
  · Ball bearing 6205 ZZ              — ₹215 vs ₹319        (33%)
  · ERW pipe 4" IS 1239 SCH 40        — ₹225 vs ₹318        (29%)

QUALITY ASSURANCE PERFORMED
  · Smoke-check data contract: 6/6 PASS
  · NMC sets byte-identical across reruns (determinism verified)
  · Full browser-tested UI (all 4 tabs, upload, approve flow, lookup)
  · Dead-code audit executed: ~30 items removed, 2 real bugs fixed
    (NMC registry never reset between runs; cluster confidence not
    rendering), all outputs proven byte-identical after cleanup

5. HOW THIS CAN CHANGE THE WORLD
================================================================================

FOR THE NATION
  · One material, one code, one price signal. When 300+ CPSEs (and
    eventually state PSUs, railways, defense) speak the same material
    language, procurement becomes comparable nationwide. The 12.6%
    average spread in our tiny 5-CPSE sample becomes visible — and
    negotiable — at national scale. On crores of rupees of annual
    procurement, even a few percent is thousands of crores saved.
  · Aggregate demand = bulk leverage. 68 shared materials in 403
    records is the seed of national rate contracts: one negotiated
    price for one NMC instead of five small orders at five prices.
  · Atmanirbhar data infrastructure. The NMC registry is sovereign,
    deterministic, and explainable — no vendor lock-in, no opaque
    model deciding what a bolt is.

FOR SAFETY
  · The veto architecture makes the dangerous failure mode — wrong
    merges that put a 10.9 bolt where an 8.8 belongs — structurally
    impossible, not just statistically rare. Zero trap violations on
    adversarial data is the proof.
  · Standardized specifications reduce spec-driven procurement errors
    and counterfeit-substitution loopholes.

FOR GOVERNANCE
  · Every code has an origin story: which CPSEs feed it, which
    attributes define it, which officer approved the ambiguous cases,
    and when. Auditors get a machine-readable trail, not a folder of
    PDFs.
  · Humans stay in charge. The AI's job is to eliminate the 99% of
    clerical drudgery; the 1% of genuine judgment stays with a named
    officer whose decision is on record.

FOR THE WORLD BEYOND INDIA
  · The pattern — extract hard facts, veto on conflict, review on
    ambiguity, hash the identity — is not India-specific. Any
    federation of independent buyers (health networks, universities,
    municipal bodies, humanitarian supply chains, even allied
    militaries) can adopt it to unify catalogs without surrendering
    control to a central authority or an unexplainable AI.
  · It is a template for trustworthy AI in high-stakes bureaucracy:
    the model never has the final word; facts and accountable humans do.

7. HOW TO RUN AND VERIFY EVERYTHING YOURSELF
================================================================================

Setup (first time):
    cd sih26099
    python3 -m venv .venv
    source .venv/bin/activate
    pip install -r requirements.txt

Run the dashboard (the demo):
    streamlit run src/app.py
    → http://localhost:8501
    (In the sidebar: upload a CSV with columns material_code, description,
     uom — data/raw/gail_materials.csv is the ready-made 5th-CPSE demo.
     Note: hot-reload is off by design; restart after code edits.)

Run the full pipeline and see the metrics:
    python src/pipeline.py
    (writes outputs/*.csv and prints precision/recall/traps)

Run the data-contract smoke test:
    python scripts/smoke_check.py
    (exit code 0 = pass)

Rebuild the deck:
    cd deck && node build_deck.js
    (requires pptxgenjs; opens UnifyMat-pitch.pptx)

Verified invariants (all automated, all passing):
    · Every one of 403 records maps to exactly one NMC (no gaps,
      no duplicates)
    · All NMCs globally unique — no code ever represents two different
      real materials
    · num_legacy_codes in the master matches actual mapping rows
    · Runs are deterministic: same inputs → byte-identical outputs
